# Healthchecker

Сервис, который по расписанию проверяет доступность заданных пользователем HTTP-целей и хранит историю результатов.

## Language

### Пользователи

**Пользователь (User)**:
Человек, вошедший в сервис через Telegram. Владеет своими мониторами, Каналами оповещения и Подключением Telegram; чужих не видит.
_Avoid_: аккаунт, учётная запись, клиент, member

**Суперадмин (Superadmin)**:
Пользователь, назначенный администратором в настройках сервиса. Видит всех пользователей, может блокировать их, ставить на паузу и возобновлять их мониторы и смотреть историю их проверок.
_Avoid_: админ, администратор, root, owner

**Сессия (Session)**:
Период, в течение которого пользователь остаётся вошедшим после входа через Telegram. Заканчивается выходом, блокировкой, истечением срока или обновлением сервиса.
_Avoid_: логин, токен, авторизация

**Блокировка пользователя (User block)**:
Обратимый запрет пользователю пользоваться сервисом: он не может войти, его мониторы не проверяются, данные сохраняются. После снятия всё возвращается как было.
_Avoid_: бан, отключение пользователя, деактивация, удаление

### Предметная область

**Монитор (Monitor)**:
Настроенная пользователем цель наблюдения: что проверять, как и с какой периодичностью.
_Avoid_: запрос, цель, эндпоинт, check

**Проверка (Check)**:
Один прогон монитора с его результатом — плановый или ручной («проверить сейчас»). История монитора — это упорядоченные проверки этого монитора.
_Avoid_: выполнение, run, execution, запуск

**Срок хранения истории (History retention)**:
Сколько хранятся проверки монитора; более старые удаляются. Одинаков для всех мониторов, включая мониторы на паузе.
_Avoid_: очистка, TTL, архив, cleanup

**Состояние монитора (Monitor state)**:
Текущее положение монитора: «неизвестно» (проверок ещё не было), «работает», «упал» или «на паузе». Определяется последней проверкой; смена между «работает» и «упал» порождает оповещение.
_Avoid_: статус (без уточнения), health, uptime

**Ожидание (Expectation)**:
Правило монитора, по которому проверка считается успешной: ожидаемый код ответа и, необязательно, фрагмент, который должно содержать тело ответа.
_Avoid_: проверяемый ответ, assertion, условие, критерий

### Оповещения

**Канал оповещения (Notification channel)**:
Адресат, которому сервис отправляет оповещения, — например, конкретный Telegram-чат. Монитор может быть привязан к нескольким каналам или ни к одному.
_Avoid_: канал (без уточнения), получатель, destination, integration

**Подключение Telegram (Telegram connection)**:
Telegram-бот пользователя, через которого отправляются оповещения во все его Telegram-каналы оповещения. У каждого пользователя своё, не больше одного. Не связано со входом в сервис.
_Avoid_: интеграция, бот (без уточнения)

**Оповещение (Alert)**:
Сообщение в канал оповещения о том, что монитор упал или восстановился.
_Avoid_: уведомление, notification, алерт

### Служебное

**Liveness**:
Состояние самого сервиса Healthchecker (живы ли API и его база). Не относится к предметной области — это служебный сигнал для инфраструктуры.
_Avoid_: health, здоровье (без уточнения), статус сервиса
