Предыдущий этап: [`0002-monitors-and-telegram-alerts.md`](0002-monitors-and-telegram-alerts.md). Термины: [`GLOSSARY.md`](../../GLOSSARY.md).

**Цель:** доделать UI, отложенный решениями 29–30 плана `0002`: страница **Монитора** с историей **Проверок**, правка, удаление, пауза и возобновление Монитора; «Тест», переименование и удаление **Каналов оповещения**; отключение **Подключения Telegram** и смена бота.

## Шаг 1. Страница Монитора и пауза

- `/monitors/[id]/+page.server.ts`: `load` — `GET /api/monitors/{id}`, `GET /api/monitors/{id}/checks?limit=50`, `GET /api/channels` (названия Каналов по `channel_ids`); 404 от backend — страница ошибки 404. Actions `pause`, `resume` (`POST /api/monitors/{id}/pause|resume`).
- `/monitors/[id]/+page.svelte` — по решению 8; `<title>` — «{название} · Healthchecker».
- Список `/`: название — ссылка; в строке форма с кнопкой «Пауза» или «Возобновить» (action на `/`, `id` в скрытом поле).

Коммит: `feat(frontend): add monitor page with check history`.

## Шаг 2. Правка и удаление Монитора

- `/monitors/[id]/edit`: `load` — Монитор и Каналы; `MonitorForm` со значениями Монитора и строкой из решения 9; action — `PUT /api/monitors/{id}`, ошибки 422 у полей, успех → `redirect(303, '/monitors/{id}')`.
- Страница Монитора: action `delete` (`DELETE /api/monitors/{id}`) → `redirect(303, '/')`; `confirm('Удалить монитор «…» вместе с историей проверок?')`.

Коммит: `feat(frontend): add monitor editing and deletion`.

## Шаг 3. Каналы оповещения

На `/channels` в строке Канала:
- «Тест» — `POST /api/channels/{id}/test`; результат виден в последней доставке.
- «Переименовать» — решение 10, `PATCH /api/channels/{id}`, ошибка 422 у поля.
- «Удалить» — `DELETE /api/channels/{id}`; `confirm` с числом Мониторов из `monitors_count` (решение 14 плана `0002`).

Коммит: `feat(frontend): manage notification channels`.

## Шаг 4. Подключение Telegram

- «Отключить Telegram» — `DELETE /api/telegram`; `confirm` с числом Каналов, которые будут удалены.
- Смена бота: форма токена доступна и при существующем Подключении. Ответ 409 — показать, сколько Каналов будет удалено, и кнопку повтора с `confirm_replace: true` (токен — в скрытом поле).

Коммит: `feat(frontend): manage Telegram connection`.

## Шаг 5. Проверка готовности

| Проверка | Как |
|---|---|
| Статика и сборка | `make check`, `npm run build` |
| Страница Монитора | из списка по названию → параметры, Состояние, Проверки; `/monitors/999` → 404 |
| Пауза | «Пауза» в списке и на странице → «на паузе», новых Проверок нет; «Возобновить» → «неизвестно», затем Проверка |
| Правка | смена названия — Состояние прежнее; смена URL — «неизвестно», Проверка на ближайшем тике; ошибка 422 у поля, введённое сохранено |
| Удаление Монитора | `confirm` → редирект на `/`, Монитора нет |
| Каналы | «Тест» приходит в чат; переименование видно в форме Монитора; удаление отвязывает Канал от Мониторов |
| Подключение Telegram | токен того же бота — Каналы сохранены; другого бота — 409, после подтверждения Каналы удалены; «Отключить» — Каналов нет |
| Без JS | все действия работают формами, без `confirm` |
| Мобильная ширина | 375px — без горизонтального скролла |
